## 2. What was migrated and why

**`cmd_vel_watchdog.py` → `src/cmd_vel_watchdog.cpp`.** This is the concrete implementation of Member 1 responsibility #9 (`/cmd_vel` interface reliability) — a deadman/watchdog that publishes a zero `Twist` to `/cmd_vel` whenever the topic has gone silent for `timeout` seconds (default 0.3 s), because `gz-sim-diff-drive-system` has no built-in command timeout and will apply the last received command forever. Logic ported 1:1: same parameter name/default, same "any message resets the timer" semantics, same 50 ms check period.

```cpp
// core of the port — see src/cmd_vel_watchdog.cpp for the full node
void check() {
  const double elapsed = (this->now() - last_rx_).seconds();
  if (elapsed > timeout_sec_) {
    pub_->publish(geometry_msgs::msg::Twist());
  }
}
```

## 3. Build system changes

`package.xml`: `<build_type>` changed from `ament_python` to `ament_cmake`; added `ament_cmake_python` buildtool dependency (so the existing, untouched Python package still installs and runs exactly as before) plus `rclcpp`/`geometry_msgs` C++ dependencies.

`CMakeLists.txt` (new): builds `cmd_vel_watchdog` as a real C++17 executable via `add_executable`/`ament_target_dependencies`, installs it to `lib/${PROJECT_NAME}` (the standard ROS 2 executable location, so `ros2 run ugv_sim cmd_vel_watchdog` needs no change). Installs the existing Python package unchanged via `ament_python_install_package()`. Installs `launch/`, `urdf/`, `worlds/`, `config/` via `install(DIRECTORY ...)` — this also **simplifies** the old setup.py, which needed a hand-written recursive-directory helper (`recursive_data_files()`) to install the deep `worlds/fuel/` tree; CMake's `install(DIRECTORY ...)` recurses by default.

**Removed** (superseded by CMakeLists.txt): `setup.py`, `setup.cfg`. Their `console_scripts` mechanism has no `ament_cmake` equivalent, so `scripts/navigation_node` and `scripts/goal_navigator` (thin `from <module> import main; main()` wrappers, three lines each, no logic) were added and installed via `install(PROGRAMS ...)` to preserve the identical `ros2 run ugv_sim <name>` invocations.

**Removed**: `ugv_sim/cmd_vel_watchdog.py` (replaced by the C++ node; keeping both would leave a stale, confusing duplicate rather than a real migration).

**Unchanged**: `launch/simulation.launch.py`'s `Node(package='ugv_sim', executable='cmd_vel_watchdog', ...)` call — it resolves to the new C++ binary with zero edits, because the executable name and package didn't change.

Matches the documented Python original's behavior exactly.
